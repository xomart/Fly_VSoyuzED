# Документация по модели движения и расчёта коррекций `FlyMagicLNS`

## 1. Назначение модуля

`FlyMagicLNS` реализует расчёт параметров коррекции орбиты КА методом узловых точек (итерационный процесс `MagicSolution`). Модуль подбирает программу управления импульсами (`ZSFlightRule`) так, чтобы к заданному витку получить требуемые параметры орбиты (или максимально приблизиться к дополнительным требованиям).  

Ключевые этапы решения:
1. Инициализация модели движения `ZMSC` по начальным условиям `ZNU`.
2. Формирование целевых параметров (основные и дополнительные требования на правом конце траектории).
3. Аналитический расчёт импульсной программы (`LNSMagicBox` / `MagicCalcU...`).
4. Численная реализация программы (`ControlImplementation`) и повторное моделирование заданного витка (`ModelForcingGivenTurn`).
5. Проверка сходимости и при необходимости коррекция «ложной цели» (`DemandIncrement`) до достижения `maxIter`.

## 2. Что можно решать: все варианты задач

### 2.1 Типы целевой геометрии орбиты (`VarOrb` / `ORB`)

- `SPO_ORB_EL = 0` — эллипс в параметрах `e, w`.
- `SPO_ORB_HBH = 1` — эллипс в параметрах экстремальной высоты `h, Bh`.
- `SPO_ORB_OMIV = 2` — орбита с приближением к ОМИВ.
- `SPO_ORB_DU = 3` — орбита с приближением к ДУ.

### 2.2 Полный список поддерживаемых вариантов (`VarKor`)

Ниже — коды задач, которые реально используются в расчёте (через `MagicCalcU10...U33`):

- **Одноимпульсные**: `10, 11, 12, 13, 14, 15, 16, 17, 18`.
- **Двухимпульсные**: `20, 21, 22, 23, 24, 241, 25, 26, 27, 28, 29`.
- **Трёхимпульсные**: `30, 31, 311, 32, 33`.
- **Тест**: `00`.

### 2.3 Семантика вариантов (кратко)

#### Орбита `EL (e,w)`
- `10..14`: коррекция одного главного параметра (`a/T/L/dL/h`) + геометрия `e,w`.
- `15..18`: частные одноимпульсные варианты без полного уточнения геометрии.
- `20..29`, `241`: двухимпульсные комбинации (`a/T/Hs/dL/L/u`) + требования к геометрии.
- `30..33`, `311`: трёхимпульсные комбинации с управлением `L` и дополнительными параметрами.

#### Орбита `HBH (h,Bh)`
- Одно- и двухимпульсные варианты нацелены на `h/Bh` и комбинации с `L/T/dL`.
- Трёхимпульсные (`30..33`, `311`) — расширенные комбинации с `L` и параметрами высоты.

#### Орбита `OMIV`
- Варианты `10..33`, `241`, `311` ориентированы на достижение целевых `a/T/L/dL/Hs/u` при максимальном приближении геометрии к ОМИВ.

#### Орбита `DU`
- Аналогично ОМИВ, но целевая геометрия формируется как «приближение к ДУ».

> Примечание: конкретные текстовые формулировки для каждого варианта выдаются методами `GetVarText`/`GetTaskText` класса `ZCLnsNpmJob`.

### 2.4 Ограничения по типам КА (`IsEnableTask`)

Поддержка задач зависит от типа аппарата (`KS`):
- **Янтарь (`0`)** — широкий набор одно/двух/трёхимпульсных вариантов.
- **Кондор (`1`)** — поддержка подмножества, включая часть задач `31..33`.
- **Аракс (`2`)** — в основном наборы `15..18` и `27..29`.

Практически: перед расчётом обязательно проверять вариант через `IsEnableVar`/`IsEnableTask`.

## 3. Параметры начальных условий (`ZNU`) — полное описание

`ZNU` — базовая структура, задающая начальное состояние движения КА.

- `Key` (`ZKEYNU`): ключ НУ (`ka`, `nom`, `mod`, `type`, `bc`).
- `numlsf`: номер логической шкалы сил (ЛШС).
- `sk`: тип системы координат (`SK_TYPE`).
- `vit`: номер витка.
- `t`: время (ссс).
- `M0`: масса КА.
- `MF`: масса топлива.
- `X[6]`: либо декартово состояние `X,Y,Z,Vx,Vy,Vz`, либо орбитальные элементы `a,e,i,W,w,u`.
- `Sb`: баллистический коэффициент.
- `Kp`: коэффициент светового давления.

### 3.1 Размерности в `ZNU`
- Координаты: **км**.
- Скорости: **км/с**.
- Углы: **радианы** (для полей в `X[6]`, если заданы орбитальные элементы).

> Внутри блока `MagicLNS` при документировании и большинстве рабочих параметров используются градусы/км/сек; конвертация задаётся соответствующими компонентами модели.

## 4. Параметры постановки задачи (`ZSMagicLnsSolution`)

`ZSMagicLnsSolution` содержит три ключевые части:

1. `MZ: ZCLnsNpmJob` — **что решать** (тип КА, тип орбиты, вариант, целевые параметры, витки импульсов, тестовые и служебные поля).
2. `MP: ZSLnsNpmPar` — **как решать** (итерации, точности, флаги уточнения, формат/объём документирования).
3. `DU: ZCDU` — **характеристики двигательной установки**.

### 4.1 `ZSLnsNpmPar` (итерационный процесс и точности)

Основные поля и смысл:
- `maxIter` — максимум итераций.
- `epsT`, `epsL`, `epsdL`, `epsu`, `epsH`, `epsBH`, `epsa`, `epse`, `epsw` — пороги сходимости по ключевым параметрам (`сек`, `град`, `км`, безразмерные).
- `isEstimateOrb*` — какие параметры геометрии орбиты уточняются итерационно.
- `ViewDim*` — размерности/представление в документировании (`T/L/dL/w/Bh/u/dV/dt`).
- `RezSave*` — что сохранять в итоговой документации и обменных формах.

Значения по умолчанию задаются `DefaultParam(...)`.

### 4.2 `ZCLnsNpmJob` (постановка цели)

Ключевые группы полей:
- Идентификация: `ka[]`, `ks`, `orb[]`, `var[]`, `ndu`.
- Целевые параметры: `parama`, `paramT`, `paramL`, `paramdL`, `paramhs`, `paramh`, `paramBh`, `parame`, `paramw`, `paramu`, `paramt`.
- Параметры массы/фокального: `m[]`, `p[]`.
- Описание импульсных точек: `vitimp[][]`, `uimp[][]`, `skimp[][]`.
- Служебное: `DemandsKey`, `SecondDemandsKey` и маски `MKN_PARAM_ORB_*`.

Через `GetParKorFromVar` и `GetAdvParKorFromVar` автоматически строятся битовые ключи того, какие параметры:
- должны быть выполнены точно;
- должны быть максимально приближены.

## 5. Выходные данные расчёта

### 5.1 `ZSFlightRule` — рассчитанная программа управления

Содержит полный профиль импульсной коррекции:
- число импульсов `n`;
- ориентации `sk[]`;
- витки/аргументы/времена приложения `vit[]`, `u0[]`, `t[]`;
- импульсы скорости `dV[]`;
- длительности работы ДУ `dt[]`, `dts[]`, `tm[]`;
- углы ориентации `alf[]`, `bet[]`;
- признак фиксированных аргументов `isFixedArg`.

### 5.2 `ZSLoopFact` — параметры орбиты в контрольных точках

Используются объекты:
- `P1` — после первого импульса;
- `P2` — после второго импульса;
- `PN` — пассивный прогноз на заданный виток;
- `PR` — расчётные параметры на заданном витке после реализации управления.

Поля включают `T`, `Hs`, `dLs`, `L`, `hmin/hmax`, `Bhmin/Bhmax`, `a,e,i,w,u` и др.

## 6. Практический порядок использования API

1. Создать контейнер задачи: `CreateMagicLnsSolution()`.
2. Заполнить `MS->MZ` (тип КА/орбиты/вариант + целевые параметры).
3. Заполнить `MS->DU` и вызвать `DefaultParam(MS->MP)` (при необходимости переопределить допуски).
4. Подготовить `ZNU`, `ZLSF`, `ZMSC`, `ZCExternalEquationsDefinition`.
5. Вызвать `MagicSolution(...)`.
6. Использовать `ZSFlightRule` и `ZSLoopFact` как результаты, при необходимости сформировать `ZPU` через `MagicMakePU(...)`.

---

## 7. Важные замечания по единицам и интерпретации

- В проекте одновременно встречаются радианы (в части НУ) и градусы (в параметрах коррекции/документации); при интеграции проверяйте конвертацию на границах API.
- Параметр `VarKor` определяет не только число импульсов, но и то, какие параметры считаются обязательными (`DemandsKey`) и дополнительными (`SecondDemandsKey`).
- Для ОМИВ/ДУ геометрия может доформировываться на первой итерации, после чего фиксируется как целевая для дальнейшей сходимости.

---

## 8. Мини-чеклист перед запуском расчёта

- [ ] Проверен вариант задачи через `IsEnableVar` для выбранного КА.
- [ ] Заполнены все обязательные параметры для выбранного `VarKor`.
- [ ] Заданы непротиворечивые НУ (`M0 > 0`, корректный `X[6]`, `vit`, `t`).
- [ ] Настроены допуски `eps*` и `maxIter`.
- [ ] Указаны характеристики ДУ (`ZCDU`) и ЛШС (`ZLSF`).
