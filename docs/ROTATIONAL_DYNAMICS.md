# Добавление уравнений вращательного движения в ядро `FlyCore`

## 1) Где расширять ядро

В текущем ядре базовая интеграция поступательного движения КА реализована в `ZMSC`:

- правая часть для базового состояния (`t, r, v, m`) считается в `ZMSC::Sph(...)`;
- размер базового состояния задается в `ZMSC::Init(...)` через `cs.n = 8`;
- в ядре уже есть механизм **добавочных уравнений** (`ZCExternalEquations`), который предназначен для интеграции дополнительного состояния вместе с базовым.

Для вращательного движения безопаснее и быстрее всего использовать уже существующий путь через `ExternalSph(...)` + `ExternalForces(...)`, без ломки текущего контура `cs.n = 8`.

---

## 2) Рекомендуемая структура дополнительного состояния вращения

Добавьте 7 дополнительных переменных (кватернион + угловая скорость):

- `q0, q1, q2, q3` — ориентация (кватернион тело→инерциальная или наоборот, но везде единообразно);
- `wx, wy, wz` — угловая скорость в связанной СК.

Итого:

- база: 8 переменных (`t, x, y, z, vx, vy, vz, m`),
- добавка: 7 переменных (`q, w`),
- полный вектор интегрирования: `N = 15`.

---

## 3) Какие уравнения добавить

### 3.1 Кинематика кватерниона

\[
\dot{\mathbf q} = \frac{1}{2}\,\Omega(\boldsymbol\omega)\,\mathbf q
\]

где `q = [q0, q1, q2, q3]^T`, а для соглашения `(q0 — скалярная часть)`:

\[
\begin{aligned}
\dot q_0 &= -\tfrac12\,(q_1\omega_x + q_2\omega_y + q_3\omega_z),\\
\dot q_1 &=  \tfrac12\,(q_0\omega_x + q_2\omega_z - q_3\omega_y),\\
\dot q_2 &=  \tfrac12\,(q_0\omega_y + q_3\omega_x - q_1\omega_z),\\
\dot q_3 &=  \tfrac12\,(q_0\omega_z + q_1\omega_y - q_2\omega_x).
\end{aligned}
\]

### 3.2 Динамика Эйлера

\[
\mathbf J\dot{\boldsymbol\omega} + \boldsymbol\omega \times (\mathbf J\boldsymbol\omega) = \mathbf M
\]

или

\[
\dot{\boldsymbol\omega} = \mathbf J^{-1}\left(\mathbf M - \boldsymbol\omega\times(\mathbf J\boldsymbol\omega)\right)
\]

где `J` — тензор инерции КА в связанной СК, `M` — суммарный момент (управляющий + возмущающий).

## 4) Как встроить в существующую архитектуру

### Шаг A. Создать класс-наследник `ZMSC`

Используйте макрос из `ZMSpaceCraft.h`:

- `ZMSC_EXHV_DEF(MyRotModel)` — если нужны и добавочные уравнения, и добавка в силы;
- переопределите `ExternalSph(...)` для вращательного состояния.

Минимально: переопределить только `ExternalSph(...)`, а `ExternalForces(...)` оставить пустым, если вращение не влияет на поступательную динамику.

### Шаг B. В `Init(...)` включить размер добавочного состояния

Перед запуском:

1. сформировать `ZCExternalEquationsDefinition`;
2. добавить 7 ID (под `q0..q3, wx..wz`);
3. вызвать `Init(..., &EED)`;
4. включить добавочные уравнения через `ExternalEquationsOn(initRotState)`.

### Шаг C. Реализовать `ExternalSph(...)`

В `ExternalSph(double t, double* mainX, double* Xexe, double* Yexe)`:

- `Xexe[0..3]` — `q`,
- `Xexe[4..6]` — `w`,
- вычислить `M(t, mainX, q, w)`,
- заполнить `Yexe[0..3] = q_dot`, `Yexe[4..6] = w_dot`.

### Шаг D. Нормализация кватерниона

После каждого шага (или раз в несколько шагов) нормализуйте `q`:

\[
\mathbf q \leftarrow \frac{\mathbf q}{\|\mathbf q\|}
\]

Практически — удобно делать в `OnMessage(...)` на событии `MMSG_SET_VECTOR`/послешаговой обработке.

---

## 5) Что нужно добавить в модель данных

Чтобы вращение стало «ядровым», а не только внешним расширением, добавьте:

1. В параметры КА (`KA`) — тензор инерции `J`, его обратную матрицу, опционально смещение ЦМ.
2. В состояние `NU`/`SI` — начальные `q` и `w`.
3. В блок сил/моментов — источники моментов:
   - двигатели/ДУ (момент от плеча),
   - аэродинамический момент,
   - гравитационный градиент,
   - солнечное давление (если есть геометрия/ЦД).

Если хотите минимальный рабочий MVP — начните только с `J` + `M_control` (заданный внешне).

---

## 6) Пошаговый план внедрения (минимальный риск)

1. Сделать прототип в наследнике `ZMSC` через `ExternalSph` (без изменений старых API).
2. Прогнать тест-кейс без моментов: `w=const`, кватернион меняется аналитически.
3. Прогнать тест Эйлера для диагонального `J` и постоянного `M`.
4. После верификации перенести поля `q,w,J` в постоянные структуры ядра.
5. Добавить вывод `q,w,M` в историю (`Story/ReStory`) и печать (`PrintManager`).

---

## 7) Критичные проверки

- Согласованность СК: где задан `w` и `M` (строго одна СК).
- Порядок кватерниона (`q0,q1,q2,q3`) не менять по коду.
- Ограничение шага интегратора при быстрых вращениях.
- Контроль `|q|-1 < 1e-8`.

---

## 8) Готовый минимум, который имеет смысл сделать первым

1. Добавить 7 внешних уравнений (`q,w`).
2. Реализовать `ExternalSph` с уравнениями выше.
3. Добавить нормализацию `q` после шага.
4. Подать простой постоянный момент `M=[Mx,My,Mz]` и сверить с эталоном.

Это даст рабочую динамику вращения в ядре интегратора без опасного рефакторинга базовой поступательной части.
